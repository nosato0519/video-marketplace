# Next product roadmap

## Principle
The first marketplace should be treated as the foundation for a product family. Every completed milestone should leave reusable components, documented decisions and tests that make the next site faster and better to build.

## After v1
1. Collect real operator feedback from the first deployment.
2. Record buyer, seller and admin friction points.
3. Convert repeated pain points into reusable modules.
4. Improve installation and update automation.
5. Improve observability, performance and security testing.
6. Add optional vertical-specific packages without duplicating the core marketplace.
7. Start the next site only after the first release has a stable baseline and a documented list of lessons learned.

## Reusable product assets
- authentication/authorization foundation
- marketplace data model
- product/catalog components
- buyer library
- seller workspace
- admin/no-code controls
- payment adapter boundary
- payout/settlement model
- private media delivery boundary
- moderation framework
- localization framework
- currency/region framework
- documentation/release tooling
- acceptance-test patterns

## Product-family strategy
The second site should not be a blind copy. Reuse the stable infrastructure while changing the business model, user journey and visual identity around the new market.

Potential directions can be evaluated later based on demand, competition, legal complexity, payment availability, support burden and expected revenue.

## Quality rule
Do not start the next site merely because the first site looks good. Start when the first site's core lifecycle is tested and the reusable foundation is trustworthy. The goal is to make each subsequent product materially better, faster to install, easier to operate and easier to sell.
