# Sales message framework v0.1

The product should be presented as a complete business platform rather than a collection of pages or a simple video-player template.

## Core message
### The simple explanation
**「動画を売るサイト」ではなく、「動画マーケットプレイスを運営するための仕組み」まで入ったシステム。**

A customer should immediately understand the three sides:

1. **購入者** — 探す、比較する、買う、見る、ダウンロードする。
2. **販売者** — 登録する、動画を出す、審査を受ける、販売する、売上を見る、出金する。
3. **運営者** — 販売者を管理する、商品を審査する、注文・売上・出金・通報を管理する、国・言語・通貨などを設定する。

## Strong value proposition
**「自分の動画販売サイトを作りたい。でも、購入者画面だけ作っても事業にはならない。」**

This product is built around the complete marketplace loop:

**販売者が登録 → 動画を登録 → 審査 → 公開 → 購入者が購入 → 動画を視聴/ダウンロード → 売上を集計 → 販売者へ精算 → 運営者が全体を管理**

That loop is the product's central selling point.

## Why the product can feel powerful
Do not sell it as "lots of features". Explain that multiple difficult systems are designed to work together:

- storefront/catalog;
- seller accounts and workflows;
- content moderation;
- orders and payments;
- seller settlement/payouts;
- private media delivery;
- localization;
- currency and region rules;
- no-code administration;
- mobile administration;
- security/audit foundations;
- installation and operational documentation.

The message is not that every integration is automatically configured. The message is that the platform architecture has the operational pieces and boundaries needed to build a real marketplace, with deployment-specific services configured during installation.

## International message
**「日本向けサイトを英語に翻訳しただけではない。」**

The architecture separates language, display currency, charge currency and region rules so the product can be adapted for international deployment.

## Non-programmer message
**「管理画面を開いて、必要な項目を入力して運営する。」**

Routine operations should not require SQL, source-code edits or server-shell commands. Advanced infrastructure work is documented separately because a self-hosted deployment still has real technical dependencies.

## Seller message
**「動画を売る人にも、ただの投稿フォームではなく“自分の販売管理画面”を用意する。」**

Emphasize drafts, resumable uploads, processing/review status, pricing transparency, sales/earnings and payout visibility.

## Buyer message
**「購入者には難しい仕組みを見せない。」**

The buyer should see a clean storefront, clear product information, transparent pricing, a straightforward purchase path and an accessible purchased library.

## Operator message
**「サイトを作ることより、サイトを運営できることを重視する。」**

The admin experience is a core product, not an afterthought.

## Sales-page structure
1. Hero: one-sentence explanation + demo CTA
2. Three-role explanation: buyer / seller / operator
3. Complete marketplace flow diagram
4. What makes it different from a simple video-selling template
5. Buyer experience
6. Seller experience
7. No-code admin experience
8. International readiness
9. Security and media-delivery architecture
10. Included documentation and self-hosted ownership
11. Supported integrations/requirements for the exact release
12. Demo/screenshots/video
13. Who it is for / who it is not for
14. License, update and support terms
15. FAQ
16. Buy/download CTA

## Short sales copy options
### Option A — direct
**動画販売サイトを作るだけじゃない。動画マーケットプレイスを運営するための土台を、ひとつに。**

### Option B — business focused
**「動画を販売できるサイト」から、「販売者・購入者・運営者が動くマーケットプレイス」へ。**

### Option C — international
**Sell videos globally. Manage the marketplace simply.**

### Option D — ownership
**自分のブランドで、自分の動画マーケットプレイスを運営する。**

## Claims policy
Marketing must not claim guaranteed security, guaranteed revenue, universal legal compliance, universal country availability or universal payment-provider support. Every feature claim must be traceable to the release acceptance checklist and tested implementation.
