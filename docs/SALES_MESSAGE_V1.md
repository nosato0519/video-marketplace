# Sales Message V1

## Core positioning
A polished, multilingual, multi-currency video marketplace platform designed for buyers, sellers and operators — with security, usability and self-hosted flexibility treated as core product requirements.

## What makes it valuable
- **Built for video commerce:** catalog, product detail, checkout, buyer library, seller workflow and moderation are designed around selling digital video.
- **Broad use cases:** suitable as a foundation for general video/digital-content marketplaces, with category-specific policy controls rather than a single-purpose design.
- **Security-minded architecture:** protected media, server-side authorization, payment verification, role separation, abuse controls, auditability and security regression testing.
- **International from the start:** multilingual UI architecture and locale-aware currency/number/date formatting.
- **Operator-friendly:** routine marketplace management is designed for non-programmers and mobile use.
- **Seller-friendly:** onboarding, drafts, resumable uploads, review states and clear validation reduce friction.
- **Buyer-friendly:** clear pricing, purchase history, library access and understandable error/status states.
- **Commercially packaged:** installation, administration, seller operation, troubleshooting, security, updates, backup/recovery and licensing documentation are part of the planned distribution package.

## Security message
> Security is treated as a product feature, not a slogan. Protected media access, server-side purchase verification, role-based permissions, abuse controls, audit trails and documented security tests are built into the product quality standard.

## Trust message
> Designed so buyers, sellers and operators each have clear controls, transparent states and practical ways to handle problems.

## Important transparency
The product must not promise absolute security or impossible piracy prevention. Hosting, infrastructure, provider policies, jurisdictional requirements and operator configuration remain part of the deployment responsibility. Optional features and provider-dependent integrations must be clearly labeled.

## Sales-page structure
1. One-sentence value proposition
2. Visual product preview
3. Three-sided value: buyer / seller / operator
4. Security differentiators with concrete controls
5. Internationalization and marketplace features
6. Admin/mobile experience
7. Installation and included documentation
8. Supported environments and external requirements
9. Demo / screenshots / test evidence
10. License and what the buyer can build/resell
11. FAQ and known limitations
12. Version, support and update policy

## Copy rule
Every sales claim must be traceable to an implemented feature, documented limitation, or release-specific test result. Never sell planned functionality as if it already exists.
